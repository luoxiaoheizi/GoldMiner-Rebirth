## 1. 在新电脑恢复开发

准备 Git、Node.js 22 或更新版本、微信开发者工具和抖音小游戏开发者工具。两平台分别需要自己的小游戏项目、真实 AppID，以及该项目的开发 / 上传权限。新电脑需重新登录开发者工具；Git 推送需另行配置有仓库写权限的账号。

在新电脑选定工作目录后执行以下 PowerShell 命令，无需沿用旧电脑的 D 盘路径：

```powershell
git clone --branch feat/chinese-minigames https://github.com/luoxiaoheizi/GoldMiner-Rebirth.git
cd GoldMiner-Rebirth
git status --short --branch
git log -1 --oneline
cd minigame
node --version
npm.cmd test
npm.cmd run preview
```

浏览器打开 <http://127.0.0.1:4173>，结束预览按 `Ctrl+C`。`npm.cmd test` 会生成预览所需的 `dist`。macOS / Linux 使用 `npm` 替代 `npm.cmd`。如果已克隆仓库，先检查并保留本地修改，再切换目标分支、执行 `git pull --ff-only`；不要用强制重置覆盖工作。

- 小游戏源码在 `minigame/`，无需 Cocos、LÖVE、Lua、Python 或旧电脑的 Codex 环境。常规构建没有第三方 npm 依赖，无需执行 `npm install`。
- `dist/`、`artifacts/`、`node_modules/` 和开发者工具私有配置不会随 Git 克隆，需要在新电脑重新生成或配置。历史浏览器截图保存在旧电脑，仓库仅保留验证记录。
- 当前构建脚本**不会读取 `.env` 文件**。AppID 通过当前进程环境变量或命令参数传入，换终端 / 换电脑需重新设置。
- 可选 `npm.cmd run test:browser` 需要新电脑已有 Playwright 及浏览器；必要时设置 `PLAYWRIGHT_MODULE` 和 `BROWSER_EXECUTABLE` 为新电脑的实际路径。配置方式见 [开发文档](./README.md#可选浏览器回归)。该脚本读取现有 `dist/web`，**不会自动构建**，源码变更后先测试或构建。
- 主体证件、授权合同、平台审核材料和凭据通过安全渠道单独交接。AppSecret、访问令牌、签名密钥不得写入源码、文档或 Git；本地单机运行目前不需要这些密钥。

### R02：抖音必接能力

抖音官方《小游戏必接能力说明》当前将**侧边栏复访**列为所有小游戏的必接能力。内购游戏才适用其中的客服要求，有自定义文字输入才适用其中的敏感词要求；本项目当前没有内购或自定义文字输入，不能直接把后两项列为必开发功能。[官方必接能力说明](https://partner.open-douyin.com/docs/resource/zh-CN/mini-game/guide/minigame/essential-skills)

当前 `src/platform.js` 未封装复访能力，`src/main.js` 和 `src/ui/renderer.js` 未提供对应流程。下一位开发者应先查看[侧边栏复访接入说明](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/operation1/ability/-retention/sidebar)，确认当时支持的 API、启动场景及检测规则，再实现和真机测试。本文不预设接口名称或奖励机制；如添加奖励，需定义防重复领取与存档规则。共享代码中仅在抖音且能力可用时展示相关操作，微信和浏览器需正常运行。

### R03：素材与名称

原项目声明图片 / 音频来自互联网并经过修改。MIT 代码许可、随包 `LICENSE` 和 `ASSET-NOTICE.txt` **不能代替素材商用授权证明**。“黄金矿工 · 重生”目前是开发中的展示名称，尚无名称 / 商标 / IP 授权核验记录。

`scripts/build.js` 当前会复制根目录 `images/`、`audios/` 下所有符合扩展名的直接子文件，包含可能未被界面实际引用的素材。替换时需同时审查最终包；必要时改为明确的资源白名单，避免未使用的旧素材仍随包发布。素材台账建议记录相对路径、用途、来源、权利人、授权范围 / 期限、证明存放位置和替换状态。敏感合同留在受控资料库，仓库只保留非敏感索引。

## 5. 最终构建顺序（必须注意）

**`npm test` 会重建三端产物，并移除产物中的 AppID，即使当前终端已设置 AppID 环境变量也一样。** 原因是构建测试直接调用不带参数的 `build()`。测试与构建不能并行；开发者工具内直接修改的生成配置也会被重建覆盖。

因此顺序固定为：修改源码 → 测试 → 可选浏览器回归 → **带真实 AppID 的最终构建** → 核对配置 → 开发者工具 / 真机验收 → 上传。最终构建之后若再次运行测试，必须重新带 AppID 构建并核对后再上传。

在 `minigame` 目录执行：

```powershell
npm.cmd test
# 若已配置 Playwright，此时可执行：npm.cmd run test:browser
# 上一步已生成最新 dist，浏览器回归读取该产物。

$env:WECHAT_APPID = Read-Host '输入微信小游戏的真实 AppID'
$env:DOUYIN_APPID = Read-Host '输入抖音小游戏的真实 AppID'
npm.cmd run build

# 核对 appid 与目标项目一致；不要在这里写入 AppSecret。
Get-Content -Encoding UTF8 dist/wechat/project.config.json
Get-Content -Encoding UTF8 dist/douyin/project.config.json
git rev-parse HEAD
Get-FileHash dist/wechat/game.js -Algorithm SHA256
Get-FileHash dist/douyin/game.js -Algorithm SHA256
```

命令出现失败时先解决，再继续下一步。可只设置准备上线的平台 AppID；构建仍生成三端，缺少另一平台 ID 的包不应当作其正式上传包。参数 `--wechat-appid` / `--douyin-appid` 也可使用，优先于环境变量。

- 微信开发者工具选择小游戏，导入 `dist/wechat`；抖音小游戏开发者工具导入 `dist/douyin`。核对真实 AppID、目标平台和项目类型，勿导入整个仓库、`dist/web` 或另一个平台目录。
- 当前方向为 `landscape`，每端入口为 `game.js`；本地图片 / 音频随包，无自建服务器运行依赖。未来增加联网接口时再核对合法域名、TLS、后端部署及隐私要求。
- 构建预算是项目自设的 4 MiB，实际可上传大小、基础库和审核规则以当前平台工具为准。不要为了让测试通过直接放宽预算而跳过平台检查。

- 最终包留存在受控发布归档中；`dist` 会被覆盖，且不在 Git 内，不能作为唯一备份。除了 `game.js` 的 SHA256，还应给完整归档生成校验值，覆盖图片、音频和配置；审核材料与敏感资料不要放进公共仓库。
